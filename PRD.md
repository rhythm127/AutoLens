Product Requirements Document (PRD): AutoLens — Remaining Implementation1. Executive Summary & Product VisionAutoLens is a manual-grounded, AI-powered vehicle troubleshooting chatbot ("See the warning. Understand the problem."). Users upload their specific vehicle's owner's manual PDF, optionally upload a photo of a dashboard warning light, and chat naturally with an AI assistant that answers strictly from the uploaded manual (never general internet knowledge), cites exact page numbers, and displays a deterministic safety severity badge (LOW / MEDIUM / HIGH).   Core Design PrinciplesNatural Chat First: Users interact with a conversational LLM (via OpenRouter, Google Gemini API, or local Ollama fallback) rather than rigid forms or hardcoded if/else chat trees.Strict Manual Grounding: Every response is grounded in chunks retrieved from the vehicle's uploaded PDF via the existing HybridRetriever (ChromaDB + BM25Plus), with visible page citations.   Deterministic Safety Guardrail: The LLM explains the manual and asks natural follow-up questions, while the existing rule-based SeverityEngine (app/safety/severity_engine.py) deterministically computes LOW / MEDIUM / HIGH severity in the background.   Zero Regressions: All existing backend modules and pytest suites must remain intact and passing.   2. Existing Codebase Inventory (Already Completed — Do Not Break)The repository (rhythm127/autolens) already contains a tested FastAPI backend:   backend/app/main.py: FastAPI app entry point with health, vehicle, RAG (/rag/ingest, /rag/search), and severity evaluation endpoints.   backend/app/rag/: Complete PDF ingestion and hybrid search pipeline (extractor.py, chunker.py, indexer.py, hybrid_retriever.py).   backend/app/safety/severity_engine.py: Deterministic LOW / MEDIUM / HIGH rule-based safety engine.   backend/tests/: Existing unit/integration tests (test_health.py, test_hybrid.py, test_indexer.py, test_rag.py, test_severity.py, test_vehicles.py).   3. Remaining Scope & Technical RequirementsMilestone 1: Manual-Grounded Conversational Chat Engine (backend/app/chat/)Create backend/app/chat/chat_service.py and wire it into backend/app/main.py.   Provider-Agnostic LLM Client:Primary: OpenRouter (OPENROUTER_API_KEY, configurable OPENROUTER_MODEL, default google/gemini-2.0-flash-exp:free) OR Google Gemini API (GEMINI_API_KEY, default gemini-2.5-flash).   Secondary: Local Ollama (http://localhost:11434/api/chat, OLLAMA_MODEL, default llama3.2).Offline Test Fallback: If no API key is set and Ollama is unreachable (e.g., during pytest), return a clean deterministic summary built directly from the top retrieved manual chunk so tests never fail due to network/keys.System Prompt Behavior:Answer only using the retrieved manual passages. If the manual lacks the answer, explicitly state that the uploaded manual does not cover it.   Cite the source document and page number(s) inline.   Conversational Diagnostic Agent Behavior: If the user mentions a dashboard warning light without specifying whether it is steady/flashing, how the vehicle is driving, or whether there is unusual noise, naturally ask those follow-up questions in the reply.   Never contradict the deterministic severity level provided by SeverityEngine.   Background Safety Integration:Automatically run SeverityEngine against the retrieved manual chunks and any detected warning/symptom keywords in the conversation to attach a structured severity object (LOW, MEDIUM, HIGH, recommended_action) alongside the chat reply. Confidence Threshold Guardrail: If confidence < 0.65 or the image is unclear, return status: "low_confidence" with a user-friendly prompt asking the user to retake the photo or describe the symbol in text.
